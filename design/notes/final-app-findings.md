# Final app findings: implementation

Scope: acceptance items 3–9. Implementation ran alone, with no new delegated review. No workflow file was changed and nothing was published.

- **3 — Fixed:** each bundled pack entry has its own initially unchecked id in `selectedLocalIds`; warnings use payload file names read on IO, and the total includes bundled entries. On virtual display `:70`, a real two-file pack showed 2 entries; selecting Beta.dll left Alpha.dll unchecked and added only Beta.dll to the Library, off. Filename regression test passes. Existing offline limitation: selected files can enter the Library before core `importPack` refuses profile creation with “Needs a connection”; this remains a follow-up outside this UI pass.
- **4 — Fixed:** new store function `stopFollowingPack(profileId)` clears only that profile's `followAddress` and `nextVersion`, without applying game files. The enabled dialog action closes the preview; it is available even when fetching the update fails. `StopFollowingPackTest` writes real persistence, shuts down, reloads, reopens the store and verifies the marker/address are absent and installed records, versions, membership and other profiles are unchanged.
- **5 — Fixed:** beta discovery reads `https://github.com/scramd/NNOMM/releases.atom` and resolves published tag links to release metadata assets. The parser follows release.yaml's beta substring rule, with alpha taking priority; numbered beta tags work. Inline Atom fixtures cover exact/numbered beta, stable, alpha, empty feeds and unrelated links; no network. Stable asset lookup is unchanged. External XML entities/DOCTYPE are disabled.
- **6 — Fixed:** danger-zone label and help now state that managed mods and only loader files NNOMM installed are removed; adopted loaders, player files, profiles and recovery copies stay. Completion text states the same ownership limit. Definitions and their generator agree. Core edits outside the new item-4 function are limited to this completion string; apply logic and real IO are untouched. Removal itself was not exercised in this pass; existing core safety tests cover IO behavior.
- **7 — Fixed:** explicit checks bypass the automatic “Never” preference, report unsupported/current/error states, and never auto-install. Unsupported-build feedback offers the existing releases-page action. Startup unsupported/current/error checks stay quiet. Test and real-mode display `:70` verified a manual check with “Never”, including the visible releases-page button; packaged Windows update/install still needs checking.
- **8 — Fixed:** the demo import warning uses the existing PacificWingSkins.dll name without adding an extension. Filename test and dark/light wide/narrow renders verified it.
- **9 — Updated:** `design/STATUS.md` now separates implemented features, remaining core integration/review, Windows-only checks, mock deviations and decisions without the user. It records the offline pack-import limit found during this pass.
